devo leggere due sms concatenati usando la pdu e un sim900 su arduino. RXbuffer è di 64 bytes. cosa devo fare
ChatGPT ha detto:

Sì: con un SIM900 e buffer RX da 64 byte, la cosa importante è non aspettare che l'intero SMS concatenato arrivi in una sola volta. Devi gestire la ricezione come uno stream, accumulando i dati e ricostruendo i segmenti.

Se parli di SMS concatenati PDU, la procedura tipica è:

    Metti il SIM900 in modalità PDU:

    AT+CMGF=0

    Quando leggi un SMS con AT+CMGR, il SIM900 ti restituisce una PDU che può essere più lunga dei 64 byte.

    Devi quindi leggere la seriale a blocchi, senza usare un buffer che debba contenere tutta la PDU.

    Dalla PDU devi estrarre l'UDH (User Data Header). Per gli SMS concatenati contiene normalmente:

        riferimento concatenazione

        numero totale dei segmenti

        numero del segmento corrente

    Tipicamente trovi qualcosa del tipo:

    05 00 03 XX 02 01

    dove:

        XX = riferimento

        02 = 2 segmenti totali

        01 = segmento 1

    Salvi ogni segmento separatamente, ad esempio:

    struct SmsPart {
        uint8_t ref;
        uint8_t total;
        uint8_t part;
        String data;
    };

    Quando hai ricevuto:

    part 1/2
    part 2/2

    li ordini per part e ricomponi il messaggio.

Attenzione ai 64 byte

Non fare una cosa del genere:

char buffer[64];

Serial.readBytesUntil('\n', buffer, 64);

perché una PDU può tranquillamente superare i 64 byte e rischi di perdere/troncare la ricezione.

Meglio fare un parser a macchina a stati, leggendo un carattere alla volta:

while (Serial1.available()) {
    char c = Serial1.read();

    // passa c al parser
    processPduChar(c);
}

Il parser può accumulare temporaneamente i caratteri esadecimali e trasformarli in byte:

uint8_t hexToByte(char h, char l)
{
    auto hex = [](char c) -> uint8_t {
        if (c >= '0' && c <= '9') return c - '0';
        if (c >= 'A' && c <= 'F') return c - 'A' + 10;
        return c - 'a' + 10;
    };

    return (hex(h) << 4) | hex(l);
}

In questo modo non hai bisogno di avere tutta la PDU in RAM.
Però c'è un dettaglio importante

Per dirti esattamente come ricomporre i tuoi SMS devo sapere che tipo di concatenazione sta usando il SIM900 e, soprattutto, vedere una PDU reale.

Se mi incolli, per esempio, l'output di:

AT+CMGF=0
AT+CMGL="ALL"

oppure una singola risposta:

AT+CMGR=...

posso indicarti byte per byte dove sono UDH, riferimento, numero dei segmenti e numero del segmento, e prepararti il codice Arduino compatibile con buffer RX da 64 byte.

ChatGPT ha detto:

Sì. Se intendi che il TP-UD (User Data) è 8-bit, allora cambia parecchio: non devi trattare il contenuto come testo GSM 7-bit.

Per SMS concatenati 8-bit, nell'UD trovi normalmente un UDH con IEI 00, quindi una struttura tipica è:

05 00 03 XX NN PP

dove:

    05 = lunghezza UDH

    00 = IEI concatenazione a 8 bit

    03 = lunghezza dell'IE

    XX = riferimento concatenazione

    NN = numero totale dei segmenti

    PP = numero del segmento corrente

Quindi, ad esempio:

05 00 03 7A 02 01

significa segmento 1 di 2, con riferimento 0x7A.
Con buffer da 64 byte

La soluzione migliore è non cercare di contenere la PDU intera nel buffer. Il buffer da 64 byte deve essere semplicemente un buffer di ricezione temporaneo:

uint8_t rxBuffer[64];

Ricevi a blocchi, analizzi la PDU e, appena individui:

UDHL = 05
IEI  = 00
IEDL = 03
REF
TOTAL
PART

salvi i dati del segmento in una struttura dedicata.

Per esempio:

struct SmsSegment {
    uint8_t ref;
    uint8_t total;
    uint8_t part;
    uint16_t len;
    uint8_t data[140];
};

Ma attenzione: se il tuo SMS è davvero 8-bit, bisogna sapere se vuoi conservare i dati come byte binari oppure se quei byte rappresentano testo codificato (per esempio UTF-8 o altro).

Se mi dai una PDU reale del SIM900 (anche oscurando numero di telefono e dati sensibili), posso dirti esattamente quali byte leggere e come ricostruire i due SMS con soli 64 byte di RX buffer, compreso il codice Arduino.
